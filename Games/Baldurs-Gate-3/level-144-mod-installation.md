# Установка модов для персонажа 144-го уровня

Пошаговая инструкция для **Baldur's Gate 3 на Windows 11, GOG, Patch 8 / Hotfix #36**, версия игры `4.1.1.7209685`. Здесь собрана техническая часть [билда со всеми 12 классами](level-144-all-classes-build.md): повышение предела до 144, точная выдача опыта через консоль и уменьшение лишних ОЗ до уровня обычного персонажа 12-го уровня.

Проверено по актуальным страницам авторов **2 августа 2026 года**. Сам файл Level 144 помечен автором как совместимый с Patch 8, но его работа именно на Hotfix #36 должна быть подтверждена контрольной новой игрой до начала настоящего прохождения.

## Короткий ответ: что потребуется

| Компонент | Актуальный вариант | Для чего нужен |
|---|---|---|
| Игра | Patch 8 / Hotfix #36, `4.1.1.7209685` | Целевая версия сборки |
| .NET | **.NET 8 Desktop Runtime x64** | Требование BG3 Mod Manager, не самого мода |
| Visual C++ | Актуальный **Microsoft Visual C++ Redistributable x64** | Требование BG3 Mod Manager и его библиотек |
| Менеджер | **BG3 Mod Manager 1.0.12.9** или более новый совместимый релиз | Импорт `.pak` и запись порядка загрузки |
| Мод уровня | **Level 144 - No XP Modifier Required v1.3.1**, 122 KB, file ID `90427` | Повышает предел уровня и содержит собственную таблицу XP |
| Консоль и runtime | **Norbyte BG3 Script Extender v32** или более новый релиз для Patch 8 | Нужен для консоли XP и мода ОЗ |
| Меню настроек | **Mod Configuration Menu (MCM) 1.40.1** или более новый совместимый релиз | Удобно и безопасно задаёт параметры мода ОЗ |
| Коррекция ОЗ | **Scaling Difficulty 1.5.2.0** или более новый совместимый релиз | Даёт отдельную плоскую поправку к максимуму ОЗ категории `Player` |

Сам `Level 144 v1.3.1` — **standalone**. Script Extender, MCM и Scaling Difficulty не нужны ему для работы. Они входят в полную сборку потому, что Script Extender даёт консоль XP, а связка Script Extender + Scaling Difficulty + MCM реализует выбранную коррекцию ОЗ.

> `No XP Modifier Required` означает «не нужен отдельный множитель опыта», а не «используется неизменённая ванильная таблица». Мод сам включает `XPData.txt`; поэтому нельзя добавлять ещё один XP-мод без специальной проверки конфликта.

## Что не нужно ставить «на всякий случай»

| Компонент | Решение для этой сборки | Причина |
|---|---|---|
| `UnlockLevelCurve` или другой level-cap | **Не ставить** | Переписывает ту же прогрессию и конфликтует с standalone Level 144 |
| `XP Modifier`, ×10/×100/×1000 | **Не ставить** | Не нужен для точного однократного начисления и продолжит менять весь будущий XP |
| `Mod Fixer` / `ForceRecompile.txt` | **Не ставить** | Larian исправила соответствующую проблему и блокирует старый файл начиная с Patch 7 |
| `ImprovedUI`, `ImpUI`, `ImpUI Assets` | **Не требуется** | Level 144 не объявляет такую зависимость; ставить только ради другого мода, который прямо её требует |
| `Community Library` | **Не требуется** | Универсальной обязательной библиотекой не является |
| `Compatibility Framework` | **Не требуется** | Нужен только модам, которые специально используют его API |
| `Native Mod Loader` | **Не требуется** | Это отдельная система для нативных DLL-модов, не замена Script Extender |
| `Achievement Enabler` | **Не требуется** | Script Extender уже имеет `EnableAchievements = true` по умолчанию |
| Отдельный LSLib/Divine | **Не требуется для установки** | Нужные функции чтения `.pak` уже встроены в BG3MM |
| `Choose Your Stats` | **Не ставить ради ОЗ** | Его повторяемое уменьшение по 5 ОЗ слишком неудобно для поправки порядка 1344 ОЗ |
| Разовая команда `SetHitpoints` | **Не использовать как cap** | Меняет текущее, а не максимальное здоровье |
| Разовая `AddBoosts(...IncreaseMaxHP...)` | **Не использовать как основной способ** | Не управляет жизненным циклом пересчётов, загрузок и Wild Shape так надёжно, как готовый актуальный мод |

`Edit XP Configurator` — не дополнительная зависимость, а **альтернатива** готовому Level 144 на случай, если тот не пройдёт контрольный тест. Одновременно их использовать нельзя.

## Где находятся нужные папки GOG

В инструкции корень установки игры обозначен как `<BG3_GOG>`. Не подставлять случайный путь из чужого гайда: диск и каталог зависят от выбранного места установки.

Чтобы найти свой корень игры в GOG Galaxy:

`Baldur's Gate 3 → кнопка настроек рядом с Play → Manage installation → Show folder`

| Назначение | Путь |
|---|---|
| Корень игры | `<BG3_GOG>` |
| Game Data Path для BG3MM | `<BG3_GOG>\Data` |
| Обычный executable | `<BG3_GOG>\bin\bg3.exe` |
| DirectX 11 executable | `<BG3_GOG>\bin\bg3_dx11.exe` |
| Script Extender | `<BG3_GOG>\bin\DWrite.dll` |
| Настройки Script Extender | `<BG3_GOG>\bin\ScriptExtenderSettings.json` |
| Пользовательские `.pak`-моды | `%LOCALAPPDATA%\Larian Studios\Baldur's Gate 3\Mods` |
| Порядок загрузки | `%LOCALAPPDATA%\Larian Studios\Baldur's Gate 3\PlayerProfiles\Public\modsettings.lsx` |
| Сохранения | `%LOCALAPPDATA%\Larian Studios\Baldur's Gate 3\PlayerProfiles\Public\Savegames\Story` |

## Шаг 1. Подготовить чистую игру и резервную копию

1. В GOG Galaxy обновить игру и при необходимости выполнить **Manage installation → Verify / Repair**.
2. Запустить BG3 без модов хотя бы один раз до главного меню и закрыть. Так создаются профиль `Public` и пользовательские папки.
3. Проверить в главном меню номер `4.1.1.7209685`.
4. Закрыть игру, GOG Launcher и старые менеджеры модов.
5. Скопировать в отдельную резервную папку:
   - `%LOCALAPPDATA%\Larian Studios\Baldur's Gate 3\PlayerProfiles\Public`;
   - `%LOCALAPPDATA%\Larian Studios\Baldur's Gate 3\Mods`, если она уже существует;
   - архивы точных версий уже используемых модов, если они есть.

GOG Cloud сохраняет игровые сейвы, но не гарантирует восстановление точных `.pak`, их версий и порядка загрузки. Поэтому это не замена локальной копии.

## Шаг 2. Установить системные компоненты BG3MM

Установить официальные версии Microsoft:

1. [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/en-us/download/dotnet/8.0) — выбрать **Windows x64** именно в разделе **Desktop Runtime**. Отдельный обычный `.NET Runtime` после этого не нужен.
2. [Microsoft Visual C++ Redistributable x64](https://aka.ms/vs/17/release/vc_redist.x64.exe).
3. Перезагрузить Windows, если установщики этого потребуют.

Старые инструкции про `.NET Framework 4.8` относятся к прежним версиям BG3MM и для актуальной ветки `1.0.12.x` устарели.

## Шаг 3. Установить и настроить BG3 Mod Manager

1. Скачать `BG3ModManager_Latest.zip` только со страницы [официальных релизов LaughingLeader](https://github.com/LaughingLeader/BG3ModManager/releases/latest). На дату проверки последним был `1.0.12.9`.
2. Распаковать архив в обычную папку с правом записи, например `C:\Games Tools\BG3ModManager`.
3. Не распаковывать BG3MM в `Program Files` и без необходимости не запускать от администратора. Это портативная программа, отдельной установки у неё нет.
4. Запустить `BG3ModManager.exe`.
5. Если GOG-версия не определилась автоматически, открыть **Settings → Preferences** и указать:
   - `Game Data Path`: `<BG3_GOG>\Data`;
   - `Game Executable Path`: `<BG3_GOG>\bin\bg3.exe` либо используемый `bg3_dx11.exe`.
6. Сохранить настройки, полностью перезапустить BG3MM и нажать **Refresh**.
7. Проверить два поля:
   - профиль — `Public`;
   - кампания — `Main`.

В Patch 8 базовый мод кампании называется `GustavX`. Актуальный BG3MM определяет его сам; вручную добавлять старые `Gustav` или `GustavDev` не нужно.

## Шаг 4. Установить Script Extender и включить консоль

### Предпочтительный способ

1. В BG3MM выбрать **Tools → Download & Extract the Script Extender**.
2. Убедиться, что появился файл `<BG3_GOG>\bin\DWrite.dll`.
3. Запустить игру один раз при включённом интернете. `DWrite.dll` является updater: подходящий runtime Script Extender он получает и обновляет при запуске игры. Новый GitHub-релиз не создаётся для каждого обновления runtime.
4. В главном меню проверить строку о загруженной версии Script Extender. Текущий публичный updater на дату проверки — `v32` от 21 июня 2026 года; более новый совместимый runtime допустим.
5. Закрыть игру.

### Если установка через BG3MM не сработала

Скачать последний релиз с [официальной страницы Norbyte](https://github.com/Norbyte/bg3se/releases), извлечь из архива `DWrite.dll` и положить его непосредственно в `<BG3_GOG>\bin`. Не устанавливать вместо него Native Mod Loader и не переименовывать чужие DLL.

### Включить постоянное консольное окно

В **Settings → Preferences → Script Extender** включить `Create Console` и сохранить настройки. Если этого пункта нет, вручную создать рядом с `DWrite.dll` файл `ScriptExtenderSettings.json` с содержимым:

```json
{
  "CreateConsole": true
}
```

В Проводнике Windows заранее включить показ расширений файлов и проверить, что имя не стало `ScriptExtenderSettings.json.txt`. При правильной настройке вместе с игрой открывается второе чёрное окно консоли. Старый совет нажимать `F11` для нашей процедуры не нужен.

Script Extender документирует `EnableAchievements = true` как значение по умолчанию. Это сторонний способ вернуть достижения, а не гарантия Larian; отдельный Achievement Enabler в эту сборку не добавлять.

## Шаг 5. Скачать ровно нужный файл Level 144

1. Открыть вкладку [Custom Level Cap — Files](https://www.nexusmods.com/baldursgate3/mods/7101?tab=files).
2. В разделе **Main files** найти строку:
   - `Level 144 - No XP Modifier Required`;
   - версия `1.3.1`;
   - размер `122 KB`;
   - file ID `90427`;
   - дата загрузки 24 апреля 2025 года.
3. Использовать **Manual Download**. Кнопка Nexus `Mod Manager Download` рассчитана прежде всего на Vortex, а наша инструкция использует BG3MM.
4. Не брать:
   - старый `Level 144 v1.3` из `Old files`;
   - Level 20/40/60/120/240/400;
   - `Level 40 Compatibility mode`;
   - другой Unlock Level Curve.

В шапке всей страницы Nexus может отображаться общее старое `Version 1.1`. Для сборки имеет значение версия **конкретной строки файла** — `1.3.1`.

## Шаг 6. Импортировать Level 144 и записать порядок

1. В BG3MM выбрать **File → Import Mod** и указать скачанный архив. Можно также перетащить архив в окно программы.
2. Не создавать вручную подпапку внутри `%LOCALAPPDATA%\Larian Studios\Baldur's Gate 3\Mods`: `.pak` должен находиться непосредственно в корне `Mods`. BG3MM сделает это сам.
3. Переместить Level 144 из `Inactive Mods` в `Active Mods`.
4. Навести указатель на мод и убедиться, что BG3MM не показывает красных отсутствующих зависимостей.
5. Для первого теста оставить активным только Level 144. Script Extender в списке `.pak` не появляется — это нормально, он загружается через `DWrite.dll`.
6. Ещё раз проверить `Public` и `Main`.
7. Нажать **Export Load Order to Game** либо **File → Export Order to Game**.
8. Полностью закрыть BG3MM и запустить игру. После экспорта можно запускать через GOG Galaxy или BG3MM; менеджер не обязан оставаться открытым.

Во встроенном менеджере Larian файл может отображаться как `Third-party`. Это описание происхождения, а не доказательство ошибки. Не пытаться попеременно обновлять и переставлять тот же файл встроенным менеджером и BG3MM.

## Шаг 7. Обязательный smoke test перед настоящим прохождением

Публичного подтверждения полноценного теста `Level 144 v1.3.1` именно на Hotfix #36 нет. Файл выпущен для Patch 8, но в комментариях встречаются неподтверждённые сообщения об остановке прогрессии, пропавших выборах второго класса и старых вылетах выше 72. Поэтому одной надписи «уровень 144» недостаточно.

1. Активны только Level 144 и Script Extender.
2. Создать **нового** Dark Urge с начальным Ranger по [основному гайду сборки](level-144-all-classes-build.md).
3. После получения управления на наутилоиде сделать отдельное ручное сохранение до начисления XP.
4. Убедиться, что вместе с игрой открыто консольное окно. Переключиться в него и нажать `Enter`; если команда не принимается в серверном контексте, ввести `server`.
5. Начислять опыт только порциями из шага 8 ниже, завершая предложенные повышения между порциями. Не выдавать сразу всё число до проверки фактической таблицы `XPData.txt` установленного `.pak`.
6. Создавать новые контрольные сохранения и перезагружать их минимум после уровней 12, 13, 20/21, 72, 120 и 144.
7. Проверять на каждом блоке:
   - можно ли перейти выше уровней 12 и 20;
   - появляются ли все экраны выбора нового класса и подкласса;
   - не пропадают ли Expertise, Feats, Fighting Styles, Invocations, Arcane Shots, заговоры и новые круги заклинаний;
   - сохраняются ли классовые действия после выхода в меню и повторной загрузки;
   - есть ли золото у торговцев и выпадают ли алхимические ингредиенты.

Если второй класс показывает только способности первого уровня, отсутствует обязательный экран выбора, повышение зависает или игра падает на воспроизводимом уровне, **не продолжать основное сохранение**. Вернуться к сейву до XP и сначала исключить конфликт либо заменить level-cap альтернативой.

Вся последовательность выборов на 144 повышениях находится в [гайде персонажа 144-го уровня](level-144-all-classes-build.md). `AddExplorationExperience` описана Larian как выдача опыта партии игрока, поэтому процедуру безопаснее выполнять на наутилоиде до присоединения спутников.

## Шаг 8. Выдать дополнительный опыт через консоль

У BG3 нет штатной пользовательской консоли. `CreateConsole` у Script Extender открывает **отдельное чёрное окно Windows**; клавиша `~` для этой инструкции не используется.

1. Загрузить сохранение и дождаться, пока Dark Urge можно управлять.
2. Переключиться в окно BG3SE и нажать `Enter`, чтобы перейти из журнала в режим команд.
3. При необходимости ввести `server`. Приглашение должно стать похожим на `S >>`.
4. Проверить, кого вернёт `GetHostCharacter()`:

```lua
_P(Ext.Entity.Get(Osi.GetHostCharacter()).DisplayName.Name)
```

Если напечатано имя созданного Dark Urge, цель верна. В одиночной игре это ожидаемый главный аватар; в сетевой игре и для спутников нельзя полагаться только на выбранный портрет.

5. Создать отдельное ручное сохранение `XP_TEST_BEFORE`.
6. Проверить функцию минимальной обратимой пробой:

```lua
Osi.AddExplorationExperience(Osi.GetHostCharacter(), 1)
```

Убедиться, что опыт вырос ровно на 1 и консоль не показала ошибку, затем **загрузить `XP_TEST_BEFORE`**, чтобы тестовая единица не осталась.

Общая команда имеет вид:

```lua
Osi.AddExplorationExperience(Osi.GetHostCharacter(), X)
```

`X` — количество **добавляемого** опыта, а не номер уровня, не итоговый XP и не множитель. Букву `X` печатать нельзя: вместо неё подставляется целое число. Документированная Norbyte краткая запись без `Osi.` эквивалентна, но полностью квалифицированный вариант выше менее двусмыслен.

### Когда допустимо число 35 750

Если в фактически установленном `XPData.txt` все 143 перехода от 1-го до 144-го уровня стоят по 250 XP и у нового героя накоплено 0 XP, то:

```text
143 × 250 = 35 750 XP
```

и полная разовая команда была бы:

```lua
Osi.AddExplorationExperience(Osi.GetHostCharacter(), 35750)
```

Страница Nexus сама не публикует итог `35 750`, поэтому сначала нужно проверить именно архив file ID `90427` или подтвердить цену переходов на тестовом сохранении. Если герой уже получил опыт, из требуемого совокупного порога нужно вычесть уже накопленное значение. Надёжной команды «отменить выданный XP» не документировано; откат — загрузка резервного сохранения.

Для нашей последовательности безопаснее выдавать подтверждённые 250-XP переходы блоками:

| Довести общий уровень | Добавить XP | Завершить повышения |
|---:|---:|---|
| 12 | 2 750 | Ranger 1–12 |
| 13 | 250 | Cleric 1 |
| 14 | 250 | Rogue 1 |
| 17 | 750 | Bard 1–3 |
| 28 | 2 750 | Rogue 2–12 |
| 37 | 2 250 | Bard 4–12 |
| 48 | 2 750 | Cleric 2–12 |
| 60 | 3 000 | Barbarian 1–12 |
| 72 | 3 000 | Druid 1–12 |
| 84 | 3 000 | Fighter 1–12 |
| 96 | 3 000 | Monk 1–12 |
| 108 | 3 000 | Paladin 1–12 |
| 120 | 3 000 | Sorcerer 1–12 |
| 132 | 3 000 | Warlock 1–12 |
| 144 | 3 000 | Wizard 1–12 |
| **Итого** | **35 750** | **143 повышения** |

Пример первой порции после перезагрузки чистого сохранения:

```lua
Osi.AddExplorationExperience(Osi.GetHostCharacter(), 2750)
```

После каждой порции полностью пройти экраны повышения и создать новый контрольный сейв. Команда `exit` возвращает окно BG3SE в режим журнала. Когда XP больше не требуется, можно поменять `CreateConsole` на `false` и перезапустить игру; сам Script Extender продолжит работать для модов.

## Шаг 9. Установить MCM и Scaling Difficulty для коррекции ОЗ

Эту часть выполнять **после успешного теста Level 144**. Саму отрицательную поправку включать только после завершения всех 144 повышений.

### Скачать и записать порядок

1. Скачать через **Manual Download** актуальный [Mod Configuration Menu](https://www.nexusmods.com/baldursgate3/mods/9162). На дату проверки это версия `1.40.1`; она требует Script Extender v29+.
2. Скачать через **Manual Download** актуальный [Scaling Difficulty](https://www.nexusmods.com/baldursgate3/mods/16723). На дату проверки это версия `1.5.2.0`; Script Extender обязателен, MCM формально необязателен, но для нашей настройки настоятельно рекомендуется.
3. Импортировать оба архива через **File → Import Mod**, перенести в `Active Mods` и выставить порядок сверху вниз:

| Позиция | `.pak` | Почему |
|---:|---|---|
| 1 | Mod Configuration Menu | Фреймворк должен находиться выше использующих его модов |
| 2 | Scaling Difficulty | Пользователь MCM; его автор разрешает любую позицию вне этого ограничения |
| 3 | Level 144 | Standalone-мод прогрессии; Script Extender в этом списке не появляется |

4. Выполнить **Export Order to Game**, запустить игру и открыть MCM через меню `Esc` или клавишей `Insert`.

### Сначала отключить все лишние эффекты

`Scaling Difficulty` по умолчанию умеет масштабировать противников, союзников, призывов и игроков. При уровне партии 144 это может радикально изменить всю игру. Для нашей задачи нужен **только один параметр Player HP**:

1. В MCM открыть `Scaling Difficulty → General` и нажать кнопку **Disable** — она отключает все страницы и эффекты мода.
2. Вкладку `Enable` не нажимать: она включит всё обратно.
3. В разделе `Scaling` выбрать `NPC = Player`, затем `Page = Bonus`.
4. Включить единственный флажок `Enabled` на странице `Player → Bonus`.
5. Оставить `PercentHP`, `Size`, AC, характеристики, атаку, урон, инициативу и XP равными `0`.
6. Убедиться, что страница `Player → Leveling` остаётся выключенной и её HP равен `0`.

### Рассчитать плоскую поправку

После полного достижения уровня 144:

1. Снять предметы и эффекты, временно повышающие максимум ОЗ; не использовать `Aid`, `Heroes' Feast` и Wild Shape.
2. Сделать отдельный сейв `HP_TEST_BEFORE`.
3. Записать показанный чистый максимум `H`.
4. Выбрать желаемый обычный максимум `C`. Для этого билда рекомендуется **136 ОЗ** — столько имеет Ranger 12 с CON 20:

```text
15 ОЗ на первом уровне + 11 × 11 ОЗ = 136
```

5. В `Player → Bonus → HP` ввести:

```text
K = C − H
```

Значение обычно отрицательное. Для ожидаемого чистого `H = 1480`:

```text
136 − 1480 = −1344
```

То есть в поле `HP` вводится `-1344`. Ориентир `1480` рассчитан для точной последовательности из основного гайда, первого класса Ranger, CON 20 и отсутствия `Tough`; **фактически показанный `H` важнее расчёта**.

Это плоская постоянная коррекция, а не абсолютный математический cap. Она убирает ОЗ, накопленные лишними 132 уровнями, но последующие обычные `Aid`, предметы и иные временные бонусы по-прежнему могут поднять максимум выше 136. Такой результат сохраняет смысл легальных игровых усилений.

### Не затронуть спутников

Категория `Player` может включать управляемых origin-персонажей. На вкладке `Scaling Difficulty → General` заполнить `Blacklist` именами всех спутников, которые могут войти в партию, **ровно как они отображаются на текущем языке игры**, через запятую. Имя самого Dark Urge в blacklist не добавлять.

Если игра на русском, не следует без проверки вставлять английские имена: мод сравнивает отображаемое локализованное имя. После временного присоединения каждого спутника проверить его максимум ОЗ. Для строго одиночного прохождения риск меньше, но blacklist всё равно безопаснее подготовить заранее.

### Обязательная проверка ОЗ

После ввода поправки проверить результат на копии сохранения:

1. обычное сохранение и загрузка;
2. долгий отдых и переход между регионами;
3. смерть и воскрешение;
4. respec у Иссохшего и повторный пересчёт уровней;
5. вход и выход из Wild Shape;
6. отдельное сохранение и загрузка **внутри** Wild Shape, затем выход из формы;
7. временное присоединение спутника из blacklist.

В нормальной форме Dark Urge должен возвращаться к 136 чистым ОЗ, форма друида — использовать собственный пул, а спутники — оставаться без отрицательной поправки. Если значение стало неверным, нажать `Scaling Difficulty → General → RefreshHealth` и повторить проверку. Исходный код мода хранит отдельные обычные и transformed HP и восстанавливает долю текущего здоровья, но сочетание именно с Level 144 v1.3.1 / Hotfix #36 не опубликовано автором как отдельный готовый пресет, поэтому smoke test обязателен.

### Как безопасно убрать коррекцию

До удаления `Scaling Difficulty`:

1. вернуть `Player → Bonus → HP` в `0` либо нажать общий `Disable`;
2. нажать `RefreshHealth`;
3. сохранить и снова загрузить игру, убедившись, что чистый максимум вернулся;
4. только затем перевести Scaling Difficulty в `Inactive` и снова выполнить Export.

MCM можно оставить. Level 144 нельзя удалять из сохранения с персонажем выше ванильного предела.

## Как понять, что установка выполнена правильно

- BG3MM запускается без ошибки runtime.
- В BG3MM выбраны `Public` и `Main`.
- В `Active Mods` находится ровно нужный Level 144 v1.3.1.
- После финальной настройки активны также MCM и Scaling Difficulty; порядок — MCM выше использующего его мода.
- Красных отсутствующих зависимостей нет.
- После Export создан или обновлён `modsettings.lsx`.
- В `<BG3_GOG>\bin` находится `DWrite.dll`.
- В главном меню отображается загруженный Script Extender.
- Вместе с игрой открывается отдельная консоль.
- Новый тестовый персонаж проходит уровни 12, 20 и 144 и сохраняет все обязательные экраны мультикласса после перезагрузки.
- В Scaling Difficulty выключено всё, кроме `Player → Bonus`; HP вычислен по фактическому чистому максимуму.
- Dark Urge имеет 136 чистых ОЗ в обычной форме, Wild Shape — собственный пул, спутники не изменены.

## Обновление и безопасный откат

Перед обновлением игры, Script Extender или любого `.pak` сохранить:

- `PlayerProfiles\Public`;
- папку `Mods`;
- JSON порядка из BG3MM;
- `%LOCALAPPDATA%\Larian Studios\Baldur's Gate 3\Script Extender\BG3MCM` с профилем MCM;
- исходный архив `Level 144 v1.3.1`.

После обновления BG3 сначала выполнить smoke test на копии или новом сохранении. Не загружать и не пересохранять единственную основную кампанию, пока не подтверждено, что Script Extender и Level 144 работают.

Не удалять Level 144 посреди кампании, в которой персонаж уже выше 12-го уровня. Безопасный откат — вернуть точную прежнюю версию мода и порядок либо загрузить сохранение, сделанное до установки. Scaling Difficulty перед деактивацией сначала обнулить/отключить и применить `RefreshHealth`, как описано в шаге 9.

Чтобы временно проверить чистую игру:

1. Закрыть игру.
2. Сохранить текущий порядок и резервную копию.
3. Перевести `.pak` в Inactive и экспортировать пустой порядок.
4. Для проверки без Script Extender переместить `DWrite.dll` и `ScriptExtenderSettings.json` из `bin` в отдельную резервную папку, а не удалять их безвозвратно.
5. После теста вернуть файлы и снова экспортировать нужный порядок.

Обычная переустановка или Verify / Repair не удаляет автоматически пользовательские `.pak` из `%LOCALAPPDATA%`.

## Диагностика частых проблем

| Симптом | Что проверить |
|---|---|
| BG3MM не запускается | Установлены ли .NET 8 **Desktop Runtime x64** и VC++ Redistributable x64; распакован ли весь архив |
| Не видны `Main` или моды | Правильны ли `Data` и executable; после изменения путей перезапустить BG3MM и нажать Refresh |
| Порядок сбрасывается при запуске | Нет ли подпапок в `Mods`, двух версий одного UUID, повреждённого `.pak` или ошибочного мода; не делать `modsettings.lsx` read-only |
| Игра сама отключает внешний мод | Использовать актуальный BG3MM; оставить включённой его штатную настройку `Delete ModCrashSanityCheck`, затем снова Export |
| Script Extender не загружается | Находится ли `DWrite.dll` именно в `bin` фактически запускаемой GOG-копии; запустить один раз с интернетом |
| Консоль не появляется | Включён ли `Create Console`; файл называется ровно `.json`, а не `.json.txt`; JSON не содержит лишней запятой |
| Игра не стартует с `DWrite.dll` | Временно вынести DLL и проверить чистый запуск; затем скачать свежий официальный v32 или более новый updater, не смешивая старые файлы |
| Level 144 остаётся Inactive | Выбраны ли `Public`/`Main` и выполнен ли Export после переноса в Active |
| Уровень останавливается на 12 или 20 | Точный ли это v1.3.1; нет ли второго level-cap/XP/progression-мода; повторить на новой игре |
| Пропали выборы мультикласса | Остановить прокачку; повторить с одним Level 144; это может быть несовместимость или известный неподтверждённый дефект файла |
| `Missing Mod` при загрузке | Отменить загрузку, вернуть точную версию и прежний порядок; не сохранять игру без нужного мода |
| Launcher показывает `Data Mismatch` | Проверить, что перечислены только ожидаемые `DWrite.dll` и мод-файлы; неизвестные loose-файлы требуют отдельной проверки |
| В консоли красная ошибка | По рекомендации Norbyte повторить запуск сначала только с Script Extender, без `.pak`; затем добавить один Level 144 |
| MCM не появляется | MCM стоит ли выше Scaling Difficulty; загружен ли SE v29+; открыть через `Esc` или `Insert`; временно отключить overlays и проверить другой renderer DX11/Vulkan |
| Враги или союзники стали 144-го уровня | Немедленно загрузить сейв до изменения; в Scaling Difficulty нажать общий `Disable`, затем включить только `Player → Bonus` |
| После `-1344` получается не 136 ОЗ | Использовать формулу `K = 136 − H` по фактическому чистому `H`, а не слепо повторять пример; проверить временные HP-эффекты и нажать `RefreshHealth` |
| У спутника уменьшились ОЗ | Добавить его точное локализованное отображаемое имя в `Blacklist`, нажать `RefreshHealth` и перепроверить на резервном сейве |
| После Wild Shape обычные ОЗ неверны | Вернуться к `HP_TEST_BEFORE`; проверить вход/выход и shaped save/load отдельно; не переносить настройку в основное сохранение до успешного теста |

## Что подтверждено, а что остаётся выводом

**Подтверждено источниками:**

- Hotfix #36 имеет версию `4.1.1.7209685`.
- BG3MM `1.0.12.x` требует .NET 8 и Visual C++ Redistributable и адаптирован к Patch 8.
- На дату проверки latest-релиз BG3MM — `1.0.12.9`.
- Script Extender v32 поддерживает Patch 8 и обновляет runtime автоматически.
- Конкретный файл Level 144 v1.3.1 помечен `Updated for Patch 8` и `Standalone`.
- Он изменяет `Progressions.lsx`, `Data.txt` и `XPData.txt`, поэтому другой мод уровня или прогрессии конфликтует с ним.
- Mod Fixer больше не нужен и его старый файл заблокирован Larian начиная с Patch 7.
- MCM `1.40.1` совместим с Patch 8, требует Script Extender v29+ и должен находиться выше использующих его модов.
- Scaling Difficulty `1.5.2.0` помечен как Patch 8 compatible, требует Script Extender, отдельно настраивает категорию `Player` и официально поддерживает MCM.
- В исходном коде Scaling Difficulty есть плоское поле `BonusPlayerHP`, обработчик обновления здоровья, отдельное хранение обычного и transformed/Wild Shape HP и минимальное ограничение результата в 1 ОЗ.

**Обоснованный вывод:**

- Level 144 не зависит от Steam и должен работать с Windows/GOG, потому что это обычный пакет игровых данных и BG3MM поддерживает GOG-пути. Автор не опубликовал отдельную фразу «проверено на GOG Hotfix #36».
- Script Extender v32 выпущен после Hotfix #36 и предназначен для актуальной Patch 8, но отдельного заявления Norbyte с номером Hotfix #36 нет.
- `1480` чистых ОЗ и поправка `-1344` следуют из точной последовательности 12 уровней каждого класса, первого Ranger, CON 20 и цели 136. Это расчёт билда, поэтому интерфейсное значение после полной прокачки имеет приоритет.
- Scaling Difficulty — наиболее подходящий найденный готовый мод для **плоской компенсации** лишних ОЗ; это не абсолютный cap, поскольку обычные последующие бонусы максимума здоровья продолжают действовать.

**Не найдено надёжного подтверждения:**

- что Level 144 v1.3.1 был полностью прогнан автором от 1-го до 144-го уровня на Hotfix #36;
- что пользовательские сообщения о вылетах выше 72 относятся именно к чистой v1.3.1 без конфликтов;
- что связка Level 144 v1.3.1 + Scaling Difficulty v1.5.2.0 отдельно испытана авторами на Hotfix #36 после всех 144 повышений, respec и shaped save/load;
- что существует готовый **жёсткий абсолютный** HP-cap, который блокирует даже поздние легальные временные бонусы. Предлагаемая настройка намеренно является плоской компенсацией.
